# PDToscillo

PDToscillo は、Sony PDT-FP1（Android 端末）から Tektronix 4000 シリーズ・オシロスコープを LAN 経由で
遠隔操作するアプリです。LAN ケーブルで直結し、波形取得、表示、測定、設定変更、保存、遠隔操作を行います。

```text
Sony PDT-FP1                                Tektronix 4000 Series
┌──────────────────┐   LAN ケーブル直結    ┌──────────────────────┐
│ PDToscillo       │──────────────────────▶│ Socket Server        │
│  Ethernet Network│   TCP / port 4000     │  Protocol: None      │
│  へソケットバインド│◀──────────────────────│  SCPI                │
└──────────────────┘                       └──────────────────────┘
```

PDT-FP1 では Ethernet・Wi-Fi・モバイル回線が同時に有効になり得ます。しかも LAN 直結では
インターネット到達性が無いため、Ethernet は既定ルートに選ばれません。**何もしないと
モバイル回線へ出てしまいます。** 本アプリはソケットを Ethernet の `Network` へ明示的に
バインドし、接続後にローカルアドレスを検証して誤ルーティングを検出します。

## 状態

全 6 フェーズを実装済みです。ただし**実機のオシロスコープには未接続**です。
検証済みの範囲は [docs/hardware-validation.md](docs/hardware-validation.md) で
「自動テスト済み」と「実機確認が必要」に分けて記載しています。

- [x] Phase 0: マルチモジュール構成、ビルド基盤、静的解析
- [x] Phase 1: Ethernet 検出・ソケットバインド・TCP 接続・`*IDN?`・接続診断・疑似サーバー
- [x] Phase 2: SCPI コマンドキュー・エラー処理・Capability 検出・チャンネル設定
- [x] Phase 3: 波形転送・バイナリブロック解析・Compose 描画・CSV/PNG/JSON 保存
- [x] Phase 4: トリガ（種別ごとに画面分離）・測定と統計
- [x] Phase 5: デジタル/バス・Spectrum・AFG・DVM・ファイル操作・SCPI コンソール
- [x] Phase 6: 自動測定シーケンス・Room 保存・設定画面

## アプリの使い方

### 画面の構成

下部のナビゲーションに主要 5 画面、右上のメニュー（︙）にその他の画面があります。

| 場所 | 画面 | 用途 |
| --- | --- | --- |
| 下部 | 接続 | IP とポートを入れて接続する。診断とセッションログの記録もここ |
| 下部 | 概要 | 本体の現在の状態を 1 画面で把握し、Run / Stop / Single を操作する |
| 下部 | 波形 | 波形を取得して表示する。ズーム、カーソル、CSV/PNG 保存 |
| 下部 | 測定 | 周波数や P-P 値などの測定を追加し、統計を見る |
| 下部 | コンソール | SCPI を直接送る。専用画面に無い操作はここから |
| ︙ | チャンネル | CH ごとの垂直軸・カップリング・プローブ設定 |
| ︙ | トリガ | トリガ種別・ソース・レベル・ホールドオフ |
| ︙ | オプション | デジタル / バス / スペクトラム / AFG / DVM（搭載機のみ） |
| ︙ | ファイル | 本体のファイルの保存・一覧・取り込み・削除 |
| ︙ | 自動測定 | 単発取得 → 測定 → 波形 → 保存 を指定回数繰り返す |
| ︙ | 設定 | 表示言語、接続情報、通信ログ |

接続していない画面は「接続してから利用できます」と表示され、操作できません。

### 1. 接続する

1. アプリを起動すると**接続画面**が開きます。初めての場合は「初期設定の手順」を開くと、
   オシロスコープ側の設定手順と静的 IP の設定例が出ます。
2. **IP アドレス**と**ポート**（初期候補 4000）を入力します。
3. **ソケットのバインド先**を選びます。LAN 直結なら `Ethernet（socketFactory）` のままにします。
   - `Ethernet（socketFactory）` — 既定。Ethernet の `Network` からソケットを作ります
   - `Ethernet（bindSocket）` — 上でうまくいかないときの代替
   - `システム既定（バインドなし）` — Ethernet を使わない切り分け用
4. 「接続」を押します。接続 → `*IDN?` → 機能検出まで自動で進みます。
5. 成功するとモデル名・シリアル番号・ファームウェア・チャンネル構成が表示されます。

繋がらないときは「**接続診断**」を押してください。Ethernet の検出、自分の IP、
サブネットの一致、TCP ポート、経路（モバイル回線へ出ていないか）、SCPI 応答まで
順に確認し、**失敗した項目には対処方法が併記されます**。

同じサブネットの機器を探す場合は「機器探索」を使います。上限を設けた限定的な走査で、
見つけた機器へは `*IDN?` しか送りません（設定は変更しません）。

### 2. ログを記録する（実機へ初めて接続するときは必ず）

実機で最初に接続するときは、**接続する前にログの記録を開始してください。**
接続画面の「セッションログ」で「記録開始」を押します。

記録されるもの:

- 端末の情報（機種、Android バージョン）と接続設定（IP、ポート、バインド方式）
- 開始時点のネットワーク状態（Ethernet の有無、IP、サブネット、ゲートウェイ、DNS、
  同時に有効な経路、OS が見せているインターフェース一覧）
- 経路の検証結果（モバイル回線へ出ていないか）
- **送受信した SCPI コマンドと応答のすべて**（所要時間とエラー分類つき）
- `*IDN?` の生応答、機能検出の各ステップと結果
- 接続診断の全項目と対処方法
- アプリ内部の警告・エラー

保存先はアプリ専用ディレクトリです。

```text
/data/data/com.pdtoscillo/files/logs/pdtoscillo_YYYYMMDD_HHMMSS.log
```

#### ログの取り出し方

**アプリから取り出す**（PC が無くてもよい）
「ログを送る / 保存する」を押すと共有先を選ぶ画面が出ます。
メール、ドライブ、ファイルアプリなど、送信先は毎回自分で選びます。
アプリが勝手にどこかへ送ることはありません。

**PC から取り出す**（`adb` が使える場合）

```bash
adb exec-out run-as com.pdtoscillo tar c files/logs | tar xv
```

1 ファイルだけ取り出す場合:

```bash
adb exec-out run-as com.pdtoscillo cat files/logs/pdtoscillo_20260730_120000.log > pdtoscillo.log
```

**Android のシステムログも見る場合**

アプリのログに加えて、OS 側の挙動（ネットワークの切り替えなど）も見たいときに使います。

```bash
adb logcat -v time | grep -E "RawSocketTransport|EthernetMonitor|ScpiCommandQueue|SessionLogger|PDToscillo"
```

#### 記録の注意

- ログは 10 MiB を上限とし、達したらそこで記録を止めます。
  古い行を捨てないのは、一番知りたい**最初の接続でのやり取り**を残すためです。
- 波形などのバイナリ応答は本体を記録せず、サイズと SHA-256 だけを残します。
  波形 1 回分でも数 MB になり、ログとして読めなくなるためです。
- 記録中のファイルは削除できません。停止してから削除してください。
- 連続取得を回したままにするとログが急速に増えます。調査が済んだら停止してください。

#### 実機で最初に確認したいこと

ログが取れたら、[docs/hardware-validation.md](docs/hardware-validation.md) の
「実機接続時の記録欄」へ `*IDN?` の応答を貼り付けてください。
これでモデルと世代が確定し、コマンド対応表を正確に絞り込めます。

### 3. 読み取り専用モードを解除する

接続直後は必ず**読み取り専用モード**です。値の確認はできますが、設定変更はすべて拒否されます。

設定を変えるときは、接続画面（またはコンソール画面）の「読み取り専用モード」を
オフにしてください。解除するまで、Run / Stop や垂直スケール変更などは動きません。

> 拒否は画面側ではなくコマンドキュー層で行っています。どの画面から操作しても、
> 解除していなければ本体の状態は変わりません。

### 4. 本体の状態を見る（概要画面）

モデル情報、Acquisition（モード・停止条件・取得回数）、水平軸（時間軸・レコード長・
サンプルレート）、トリガ（種別・ソース・レベル・状態）、各チャンネルの要約が並びます。

- **Run / Stop / Single / Force Trigger** をここから操作できます。
- 「自動更新」をオンにすると一定周期で読み直します。**画面が見えている間だけ**動くので、
  他の画面へ移ると止まります。周期は 200 ms〜5 s から選べます。
- 「設定を開く」からチャンネル設定画面へ移動できます。

### 5. 波形を見る（波形画面）

1. 「**取得**」を押すと、表示中のチャンネルの波形を取得して描画します。
2. 「**自動スケール**」で波形が画面に収まる範囲へ戻します。
3. チャンネルのチップで表示・非表示を切り替えます。
4. 波形の上で**ピンチすると拡大縮小**、**ドラッグで移動**します。
   ボタンの「時間 ＋/−」「電圧 ＋/−」でも操作できます。

**連続取得**をオンにすると、指定した周期で取得し続けます。
前回の取得が終わってから次の待ち時間を数えるため、応答が遅い機種でも要求が積み上がりません。
取得時間とスループットが画面に出ます。

**カーソル**は「垂直バー」「水平バー」で有効にします。波形の**左半分をドラッグすると 1 番目**、
**右半分で 2 番目**のカーソルが動き、Δt / ΔV / 1/Δt（周波数換算）が表示されます。

**保存**は CSV / PNG / JSON から選べます。保存先はアプリ専用ストレージです。

> 表示は画面の横ピクセル数に合わせて間引いていますが、区間ごとの最小値と最大値を残すため、
> 1 点だけのグリッチも消えません。保存と測定には間引く前の元データを使います。

横画面にすると波形が大きく表示され、操作パネルが右側へ寄ります。

### 6. チャンネルを設定する（チャンネル画面）

上部のチップで対象チャンネルを選び、以下を設定します。

- 画面への表示 / 非表示、ラベル
- V/div、垂直位置、オフセット、反転
- カップリング（AC / DC / DC Reject）、帯域制限、終端（50 Ω / 1 MΩ）
- プローブ減衰比（1:1 / 10:1 / 100:1）、Deskew

数値欄は**工学表記で入力できます**。`1.5n`、`2.5m`、`500k` のように書けます。
入力欄の下に解釈結果（例 `= 2.5 mV`）が出るので、送る前に確認できます。

「適用して読み戻す」を押すと、設定後に本体から値を読み直します。
**画面に出るのは本体が実際に受理した値**です。離散値へ丸められた場合は丸めた後の値が出ます。

### 7. トリガを設定する（トリガ画面）

トリガ種別を選ぶと、その種別に応じた設定項目に切り替わります。
エッジトリガではソース・スロープ・カップリング・レベルを設定でき、
「50% に合わせる」で信号振幅の中央へレベルを移動できます。

パルス幅・ラント・ビデオなどの詳細設定は未実装ですが、種別の切り替えは可能で、
**画面上に対応する SCPI コマンドを表示**しています。コンソール画面から設定できます。

### 8. 測定する（測定画面）

1. 「種類」（周波数、P-P 値、実効値など）と「ソース」を選び、「**追加**」を押します。
2. 測定値がカードで表示されます。「統計を取る」をオンにすると、
   平均・最小・最大・標準偏差・サンプル数も表示されます。
3. 「自動更新」で値を更新し続けられます。

同時に使えるスロット数は機種によって決まります（画面下部に `2 / 4` のように表示）。
測定できない状態のときは、数値ではなく「**測定不可**」と表示されます。

### 9. SCPI を直接送る（コンソール画面）

専用画面に無い操作は、公式 Programmer Manual に載っているコマンドをそのまま送れます。

- 末尾が `?` なら**問い合わせ**として応答を待ち、それ以外は**設定変更**として送ります。
- よく使う問い合わせはチップで用意してあります（`*IDN?`、`ALLEv?`、`WFMOutpre?` など）。
- 「**エラー確認**」でエラーキューを読み、何が起きたかを確認できます。
- 「スクリプト」で複数行をまとめて実行できます。`#` 以降は注釈で、**失敗した時点で中断**します。
- `*RST` やファイル削除など**危険なコマンドは確認ダイアログ**が出ます。

バイナリ応答（`CURVe?` など）はサイズと SHA-256 だけを表示します。本体は保持しません。

### 10. 自動測定（自動測定画面）

「単発取得 → 完了待ち → 測定値 → 波形 → 保存」を指定回数繰り返します。

1. **実行回数**（1〜10000）、**実行間隔**、**上限時間**を入力します。
2. 対象チャンネルと測定項目を選びます。
3. 波形の取得と CSV 保存の有無、ファイル名テンプレートを設定します。
   テンプレートでは `{source}` `{index}` `{timestamp}` が使えます。
4. 「開始」を押すと進捗が表示され、各回の結果が下に積まれます。

「エラーで停止する」をオフにすると、失敗を記録して次へ進みます。
「停止」はいつでも押せて、その回の途中でも止まります。

> 実行回数・上限時間・取得完了待ちの上限をすべて必須にしているため、無制限には走りません。

### 11. 本体のファイルを扱う（ファイル画面）

設定・画面イメージ・波形を本体へ保存し、一覧から取り込み・呼び出し・削除ができます。
取り込んだファイルはアプリ専用ストレージに置かれ、サイズと SHA-256 が履歴に残ります。

**削除**と**設定の呼び出し**は取り消せないため、確認ダイアログが出ます。

> ファイル名に親ディレクトリ参照（`..`）、引用符、改行、セミコロンは使えません。
> 入力すると理由付きで拒否されます。

### 12. オプション機能（オプション画面）

デジタルチャンネル、バス、スペクトラム（RF）、AFG、DVM を扱います。
**搭載していない機能は表示されません。** 判定できなかった機能は理由が表示されます。

AFG の**出力を有効にする操作では確認ダイアログ**が出ます。被測定回路へ実際に信号が
出るためです。現在の波形・周波数・振幅がダイアログに表示されるので、確認してから実行してください。

### 13. 表示言語を変える（設定画面）

日本語と英語を切り替えられます。既定は日本語です。
同じ画面で接続中の機器の情報と通信ログの件数を確認でき、
診断が必要なときだけ「生コマンド」をオンにして実際に送った SCPI を見られます。

## 対応予定モデル

判明している情報は「Tektronix 4000 シリーズ」のみで、正確なモデルは未確定です。
特定モデル専用の実装はせず、接続後に `*IDN?` で識別して対応機能だけを有効化します。

| 世代 | モデル例 |
| --- | --- |
| 無印 | DPO4000, MSO4000 |
| B / MDO 初代 | DPO4000B, MSO4000B, MDO4000 |
| B / C | MDO4000B, MDO4000C |

**現在確認済みの実機モデル: なし**（実機接続後に `*IDN?` の応答をここへ追記します）

詳細は [docs/compatibility-matrix.md](docs/compatibility-matrix.md) を参照してください。

## 必要環境

- Android Studio（AGP 8.10.1 に対応するバージョン）
- JDK 17（Android Studio 同梱の JBR で可）
- Android SDK Platform 36 / minSdk 30
- Sony PDT-FP1 または Android 11 以降の Android 端末

## 別の PC で clone してビルドする

計測は現場の PC と端末で行い、開発は別の PC で続ける、という進め方を想定しています。
リポジトリは自己完結しており、clone すればそのままビルドできます
（Gradle Wrapper を含むため Gradle の事前インストールは不要です）。

```bash
git clone git@github.com:NaitoMitsuharu/PDToscillo.git
cd PDToscillo
```

### Android SDK の場所を教える

**clone 直後は `local.properties` がありません**（環境ごとに異なるため git 管理から外しています）。
Android Studio でプロジェクトを開けば自動生成されますが、コマンドラインでビルドする場合は
どちらかの方法で SDK の場所を指定してください。指定しないと
`SDK location not found` で失敗します。

`local.properties` を作る場合:

```bash
echo "sdk.dir=C\\:\\\\Users\\\\<ユーザー名>\\\\AppData\\\\Local\\\\Android\\\\Sdk" > local.properties
```

環境変数で指定する場合:

```bash
ANDROID_HOME="C:\Users\<ユーザー名>\AppData\Local\Android\Sdk" ./gradlew assembleDebug
```

macOS / Linux では `~/Library/Android/sdk` や `~/Android/Sdk` になります。

### ビルドとインストール

```bash
./gradlew assembleDebug
./gradlew installDebug
```

`java` が PATH に無い環境では JDK を明示します（Android Studio 同梱の JBR で可）。

```bash
JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew assembleDebug
```

APK を直接持ち運ぶ場合は `app/build/outputs/apk/debug/app-debug.apk` を渡してインストールします。

### 現場で計測し、別の PC で続きを行う流れ

1. **開発 PC**: 変更を commit して push する
2. **現場の PC**: `git pull`（初回は clone）してビルドし、`installDebug` で端末へ入れる
3. **現場**: 端末とオシロスコープを LAN ケーブルで直結する
4. **端末**: アプリの接続画面で「セッションログ」→「**記録開始**」を押してから接続する
5. **端末**: 接続、`*IDN?`、接続診断、波形取得などを実行する
6. **端末**: 「停止」を押す（記録中はログが増え続けます）
7. **開発 PC**: 端末を USB で繋ぎ、下記でログを取り出す
8. **開発 PC**: `*IDN?` の応答を [docs/hardware-validation.md](docs/hardware-validation.md) へ記録し、
   [docs/compatibility-matrix.md](docs/compatibility-matrix.md) の該当列を確定値へ更新する

端末からログをまとめて取り出すコマンド:

```bash
adb exec-out run-as com.pdtoscillo tar c files/logs | tar xv
```

> `adb` でログを取り出せるのは `debug` ビルドのみです（`run-as` はデバッグ可能なアプリだけが対象）。
> リリースビルドを配布した場合は、アプリの「ログを送る / 保存する」から取り出してください。

## PDT-FP1 へのインストール

USB で接続し、開発者オプションの USB デバッグを有効にしてから `./gradlew installDebug` を実行します。
手順の詳細は「別の PC で clone してビルドする」を参照してください。

## LAN 直結の手順

1. PDT-FP1 とオシロスコープを LAN ケーブルで接続します。
2. オシロスコープ前面の `Utility` ボタンを押します。
3. `Utility Page` → `I/O` を選びます。
4. `Ethernet Network Settings`（または `LAN` 設定）を開きます。
5. `Socket Server` を選び、`Enabled` を `On` にします。
6. **`Protocol` を `None` に設定します**（`Terminal` ではありません）。
7. ポート番号を確認します。初期候補は **4000** です。
8. オシロスコープの IP アドレスを確認します。
9. アプリの接続画面へ IP アドレスとポートを入力します。
10. 「接続」を押し、続けて「接続診断」で各段階を確認します。

アプリ内の接続画面「初期設定の手順」からも同じ案内を開けます。

### `Protocol` を `None` にする理由

`Terminal` モードではオシロスコープが対話用のバナー・エコー・プロンプトを返すため、
プログラムからの SCPI 応答解析に干渉します。本アプリは接続直後の未要求データを破棄し、
コマンドのエコーを検出して「`None` に設定してください」と警告しますが、
正しく動かすには `None` が必要です。

### IP 設定例

直結で DHCP が使えない場合は双方に静的 IP を設定します。以下は**設定例**で、
この値でなければならないわけではありません。同一サブネットなら任意の値で構いません。

```text
PDT-FP1:
  IP アドレス     192.168.10.1
  サブネットマスク 255.255.255.0

オシロスコープ:
  IP アドレス     192.168.10.2
  サブネットマスク 255.255.255.0

ポート:
  4000
```

詳細は [docs/network-setup.md](docs/network-setup.md) を参照してください。

## 接続診断

接続画面の「接続診断」を実行すると、次の項目を順に確認して結果と対処方法を表示します。

Ethernet 検出 → PDT-FP1 の IP・サブネット・ゲートウェイ・DNS → サブネットの一致 →
TCP ポート接続 → 経路検証（モバイル誤接続の検出）→ SCPI 応答 → `*IDN?` → 応答時間 →
モデル判定 → ファームウェア → 対応機能

## e*Scope の開き方

対応機種では、オシロスコープの IP アドレスへブラウザでアクセスすると本体画面の遠隔確認や
一部操作ができます。接続後、接続画面の「e*Scope を開く」から開けます。

```text
http://<オシロスコープの IP>/
```

アプリ内 WebView と外部ブラウザのどちらでも開けます。
**e*Scope の画面を解析して非公式 API として利用することはしていません。** 表示するだけです。

## 実機なしでの動作確認（疑似サーバー）

実機がなくても、疑似オシロスコープを起動して一通り動かせます。

```bash
./gradlew :simulator:run --args="--port 4000 --model MDO4104C --verbose"
```

同じ PC の Android エミュレータから接続する場合、エミュレータ内の `10.0.2.2` がホスト PC を指します。

```text
IP アドレス   : 10.0.2.2
ポート        : 4000
バインド方式  : システム既定（バインドなし）
```

モデルや障害注入の一覧は [docs/simulator.md](docs/simulator.md) を参照してください。

## モジュール構成

| モジュール | 役割 |
| --- | --- |
| `core:model` | ドメインモデル（Kotlin/JVM、Android 非依存） |
| `core:common` | 工学単位表示、エラー分類、通信ログ、ログ抽象 |
| `core:network` | Ethernet 検出、ソケットバインド、TCP Raw Socket、経路検証、診断、機器探索 |
| `core:scpi` | コマンドキュー、応答解析、エラーキュー、Capability 検出、各種コントローラ |
| `core:waveform` | プリアンブル、波形デコード、スケーリング、デシメーション |
| `core:database` | Room、波形ファイルストア、エクスポート |
| `core:ui` | Material 3 テーマと共通 Composable |
| `feature:*` | 接続 / 概要 / 波形 / チャンネル / トリガ / 測定 / オプション / 自動測定 / ファイル / コンソール / 設定 |
| `simulator` | 実機不要の疑似オシロスコープ TCP サーバー（Kotlin/JVM） |

SCPI 解析と波形演算は Android 非依存の JVM モジュールへ寄せてあります。実機もエミュレータも
無しに単体テストと統合テストを実行できます。詳細は [docs/architecture.md](docs/architecture.md)。

## 既知の制限

- **実機のオシロスコープで未検証です。** 検証済みの範囲は
  [docs/hardware-validation.md](docs/hardware-validation.md) を参照してください。
- VXI-11 は未実装です。理由と工数は [docs/vxi11-feasibility.md](docs/vxi11-feasibility.md)。
- トリガはエッジのみ完全実装です。パルス幅・ラント・ビデオなどは種別の切り替えのみで、
  詳細設定は SCPI コンソールから行います（画面上に該当コマンドを表示しています）。
- バスの詳細設定（クロック源、ビットレートなど）、Spectrogram、マーカーは未実装です。
- Math / Reference の専用画面はありません。SCPI コンソールから操作できます。
- mDNS / DNS-SD / LXI 探索は未実装です。機器探索は同一サブネットの限定走査のみです。
- 下部ナビゲーションには主要 5 画面のみを置いています。残りは右上のメニュー（︙）から開きます。
- セッションログは 10 MiB を上限とし、達したらそこで記録を停止します（古い行は捨てません）。
- Kotlin は 2.3.21 を使用しています。Room 2.8.4 が同梱する `kotlin-metadata-jvm` が
  Kotlin 2.4 のメタデータを読めないためです。

## セキュリティ上の注意

- 本アプリは計測器を遠隔操作します。信頼できるネットワークでのみ使用してください。
- Socket Server による SCPI 通信は暗号化も認証もされません。
- 接続直後は必ず読み取り専用モードです。設定変更は明示的に解除してから行います。
  拒否は UI ではなくコマンドキュー層で強制しています。
- `*RST` / `FACTORY` / `AUTOSet` / AFG 出力の有効化 / ファイル削除は確認を必須にしています。
- 本体から返るファイル名をそのままコマンドへ差し込みません。親ディレクトリ参照・引用符・
  改行・セミコロンを含む名前は拒否します。
- 保存先はアプリ専用ストレージです。ファイル名は正規化し、保存先の外へ書き込めないようにしています。
