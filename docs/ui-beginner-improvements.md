# UI 改善指示書（オシロスコープ初心者向け）— codex 作業用

この文書は、UI 実装を担当するエージェント（codex）へ渡すための**自己完結した作業指示**です。
コードベースの前提知識が無い状態でも着手できるよう、目的・対象ファイル・具体的な変更・
制約・受け入れ条件をすべて記載します。

## 0. これは何のアプリか（前提）

- Sony PDT-FP1（Android 端末）から Tektronix 4000 シリーズ・オシロスコープを LAN 経由で
  遠隔操作する Android アプリ（Kotlin / Jetpack Compose / Material 3）。
- **想定ユーザーはオシロスコープが苦手な初心者**。現状の UI は用語も情報量も
  「計測器に慣れた人」向けで、初心者にはハードルが高い。
- 実機（PDT-FP1 + 疑似サーバーを DPO4034 の代役）での動作確認は完了済み。
  通信・接続・波形取得・保存は正しく動く。**今回はその「動く中身」を、初心者が
  扱いやすい見た目・言葉・導線にする**のがゴール。UI/UX の改善に限定する。

## 1. 今回のゴール（重視する 3 点）

ユーザーが明示した優先事項は次の 3 つ。**これ以外の大改造はしない。**

1. **用語をやさしく＋ヘルプ** — 専門用語にその場で読める説明を添える。
2. **ワンタップ自動設定（オートセット）** — 初心者でも 1 タップで「とりあえず見える」導線。
3. **画面と情報量の整理** — 密な画面を整理し、初心者に不要な数値・英語ラベル・
   分かりにくい概念（読み取り専用モード等）を見直す。

> 「かんたんモード/ガイド付きウィザードで画面を丸ごと分ける」案は**今回は採用しない**。
> 既存の画面構成を保ったまま、上記 3 点で“やさしく”する。

## 2. 触ってよい範囲 / 触ってはいけない範囲

### 触ってよい（UI 層のみ）

- `feature/*/src/main/kotlin/.../*Screen.kt`（各画面の Compose）
- `feature/*/.../*ViewModel.kt` のうち **表示用の文言・状態の整形**に関わる部分
- `core/ui/src/main/kotlin/com/pdtoscillo/core/ui/component/CommonComponents.kt`
  （共通コンポーネントの追加：ヘルプ用チップ等）
- `core/ui/.../theme/Theme.kt`（必要なら色・タイポの微調整）
- 文言・用語の言い換え、レイアウトの整理、ヘルプ文の追加

### 触ってはいけない（動作の根幹・検証済み）

- **SCPI コマンド文字列**（`core/scpi/.../TektronixCommands.kt`）。1 文字も変えない。
  未検証コマンドを増やさない。ボタンから送るコマンドは必ず `TektronixCommands` 参照。
- **コマンドキュー / 読み取り専用の強制 / エラー分類**
  （`core/scpi/.../ScpiCommandQueue.kt` ほか）。
- **ネットワーク / バインド / 経路検証 / 自動接続**（`core/network/**`）。
  「有線を固定」バインドや LAN 自動接続の仕組みは実機検証済み。ロジックを変えない。
- **安全確認ダイアログ**：Reset / Autoset / Default setup / AFG 出力 ON / ファイル削除 /
  一括適用 は必ず確認を出す。**確認を省略しない。**
- **読み取り専用モードの既定 ON**：接続直後は読み取り専用。これは事故防止の要。
  UI で“分かりやすく”するのは良いが、**安全側の初期値と拒否の仕組みは残す**（§4.3 参照）。

## 3. 現状の把握（重要な前提）

- **UI 文字列は全画面ハードコードの日本語**。`stringResource` はほぼ使っていない
  （`app/src/main/res/values/strings.xml` は存在するが画面は参照していない）。
  → 今回も**ハードコード日本語のまま**で良い。文字列リソース化は今回のスコープ外
  （やるなら別タスク。中途半端な混在は避ける）。
- **Compose UI テストが日本語ラベルを検証している**
  （`app/src/androidTest/kotlin/com/pdtoscillo/**`）。
  **ラベルや testTag を変えたら、対応するテストも必ず更新する**（§6）。
- **オートセット（Autoset）は既に存在するが前面に出ていない**：
  `feature/oscilloscope/.../OscilloscopeViewModel.kt` に確認ダイアログ付きの実装があり、
  コンソール画面にもクイックボタンがある。概要画面には Run/Stop/Single/Force Trigger は
  あるが、初心者が最初に押したい「オートセット」が目立たない。
- ktlint スタイルは `intellij_idea`（`.editorconfig`）、`max_line_length=140`。
- 主要画面（下部ナビ 5 ＋ 右上メニュー）:
  - 接続 `feature/connection/.../ConnectionScreen.kt`
  - 概要 `feature/oscilloscope/.../OverviewScreen.kt`
  - 波形 `feature/waveform/.../WaveformScreen.kt`
  - 測定 `feature/measurement/.../MeasurementScreen.kt`
  - コンソール `feature/console/.../ConsoleScreen.kt`
  - チャンネル `.../ChannelsScreen.kt` / トリガ `.../TriggerScreen.kt` /
    オプション `.../OptionsScreen.kt` / ファイル `.../FilesScreen.kt` /
    自動測定 `feature/automation/.../AutomationScreen.kt` / 設定 `.../SettingsScreen.kt`

## 4. やること（具体）

### 4.1 用語をやさしく＋ヘルプ

**(a) 用語集コンポーネントを追加**
`core/ui/.../component/CommonComponents.kt` に、ラベルの横に置ける小さな「?」を追加する。
タップすると用語の平易な説明をポップアップ（`Popup` か Material3 の `RichTooltip` /
`PlainTooltip` + `TooltipBox`）で表示する。

推奨シグネチャ（例）:

```kotlin
/** ラベル横に置く「?」。タップで用語のやさしい説明を出す。初心者向けの補助。 */
@Composable
fun HelpHint(text: String, modifier: Modifier = Modifier) { /* TooltipBox + IconButton(?) */ }

/** ラベル＋ヘルプをまとめて置く小物。 */
@Composable
fun LabelWithHelp(label: String, help: String, modifier: Modifier = Modifier) { /* Row { Text; HelpHint } */ }
```

- タッチターゲットは 44dp 以上（`core/ui/.../theme` の `MinTouchTarget` を使う）。
- ダーク/ライト両対応（既存テーマの `MaterialTheme.colorScheme` を使う。色を直書きしない）。

**(b) 用語をやさしい言葉へ**
「英語や専門用語のまま」を、初心者に通じる日本語へ。**ただし計測器の正式名称も併記**して
学べるようにする（例：「タイムベース（横軸の時間）」）。下記グロッサリを使う。

主要な言い換え・ヘルプ文（そのまま採用してよい）:

| 今の表示 | やさしい表示（例） | ヘルプ文（? に入れる） |
| --- | --- | --- |
| Acquisition | 取り込み（Acquisition） | 波形を何回、どうやって取り込むかの設定です。 |
| 水平軸 / タイムベース | 横軸（時間） | 画面の横方向＝時間です。1 目盛りが何秒かを決めます。 |
| 垂直軸 | 縦軸（電圧） | 画面の縦方向＝電圧です。1 目盛りが何ボルトかを決めます。 |
| トリガ | トリガ（波形を止める基準） | 「この条件になったら波形を表示」という基準点。安定表示に必要です。 |
| サンプルレート | サンプルレート（1秒の測定回数） | 1 秒間に何回測るか。速い信号ほど大きい値が要ります。 |
| レコード長 | 記録点数 | 1 回の取り込みで記録する点の数です。 |
| V/div | 1目盛りの電圧（V/div） | 縦 1 目盛りが何ボルトか。小さくすると波形が拡大します。 |
| 時間/div | 1目盛りの時間 | 横 1 目盛りが何秒か。小さくすると時間が拡大します。 |
| カップリング | 入力の結合（AC/DC） | DC=そのまま、AC=直流成分を除いて交流だけ見ます。 |
| プローブ減衰比 | プローブ倍率（10:1 等） | プローブの目盛り換算。実物のプローブ表示に合わせます。 |
| 帯域制限 | 帯域制限（高い周波数を抑える） | ノイズが多いとき高域を抑えて波形を見やすくします。 |
| 終端 | 終端（50Ω/1MΩ） | 入力の受け方。通常は 1MΩ。高周波は 50Ω を使うことがあります。 |
| Peak Detect | ピーク検出 | 一瞬のトゲ（グリッチ）も逃さず捉えるモードです。 |
| Hi-Res / Average | 高分解能 / 平均化 | ノイズを減らして波形を滑らかにするモードです。 |
| カーソル（Δt/ΔV） | 測る線（時間差/電圧差） | 2 本の線で、時間差・電圧差を読み取れます。 |
| Run / Stop / Single | 連続 / 停止 / 1回 | 連続表示・停止・1 回だけ取り込み。 |
| Force Trigger | 強制取り込み | 条件が来なくても今すぐ 1 回取り込みます。 |
| 読み取り専用モード | 見るだけモード（安全） | 誤操作で本体設定を変えないための保護。変更するときだけ解除します。 |
| e*Scope | 本体のWeb画面 | オシロ本体をブラウザで見る機能（対応機種のみ）。 |
| Capability / 機能検出 | 使える機能の判定 | 接続した機種で何が使えるかを自動で調べた結果です。 |
| RF / AFG / DVM / バス | （そのまま＋ヘルプ） | RF=電波測定, AFG=信号発生, DVM=電圧計, バス=通信信号の解読（搭載機のみ）。 |

- 適用箇所：概要 / チャンネル / トリガ / 測定 / 波形 の各画面のラベル。
- **すべてに ? を付ける必要はない**。初見で意味が取りづらい用語に絞る（上表が目安）。

**(c) グロッサリ画面（任意・推奨）**
設定画面（`SettingsScreen.kt`）に「用語集（オシロスコープの言葉）」の項目を足し、
上表の内容を一覧で読めるようにする。小さな学習コーナー。

### 4.2 ワンタップ自動設定（オートセット）

初心者が接続後に**最初に押せばとりあえず波形が見える**導線を前面に出す。

- **概要画面（OverviewScreen）** に「**自動で見やすくする（オートセット）**」ボタンを
  目立つ位置（Run/Stop 群の近く、または上部）に追加する。
  - 実体は既存の Autoset（`OscilloscopeViewModel` の確認ダイアログ付き実装）を使う。
    **確認ダイアログは残す**（本体設定を変える操作のため）。ダイアログ文面を初心者向けに:
    「本体を自動調整して、波形が画面に収まるようにします。よろしいですか？」
  - 読み取り専用モード中は「見るだけモードのため実行できません。解除しますか？」と促す
    導線を出す（解除は §4.3 の分かりやすいトグルへ誘導）。
- **波形画面（WaveformScreen）** には既に「自動スケール」がある（表示側の調整）。
  こちらは本体を変えず表示だけ合わせるので、ラベルを「画面に合わせる（表示だけ）」に
  変え、オートセット（本体調整）との違いがヘルプで分かるようにする。
- 接続直後の概要画面に、初心者向けの一言ガイドを出す（例：
  「まず『自動で見やすくする』を押すと、波形が画面に収まります」）。
  1 回見たら消える/小さくたためる程度で良い（過剰にしない）。

### 4.3 画面と情報量の整理

- **読み取り専用モードを分かりやすく**：現在は「読み取り専用」トグル。初心者には意味が
  伝わらない。表示を「**見るだけモード（安全）**」に変え、ON/OFF の意味を明示:
  - 見るだけモード ON = 「本体の設定は変えません（安全）」
  - 解除するとき = 「設定を変更できるようにします」＋ ? ヘルプ。
  - **既定 ON と、キュー層での拒否は変えない**（表示だけ分かりやすくする）。
- **概要画面の情報を段階表示**：初心者に不要な細目（レコード長・サンプルレートの生値、
  通信遅延、一括取得時間など）は「詳しい情報」に折りたたむ。最初は
  「モデル / 状態(連続/停止) / 横軸・縦軸のざっくり値」など要点だけ。
- **英語ラベルの日本語化**：`Run/Stop/Single/Force Trigger/Sample/Peak Detect/Hi-Res/
  Average` などのボタン表示を日本語（＋必要なら英語併記）へ。§4.1 の表に準拠。
- **チャンネル/トリガ画面**：専門項目が縦に長い。よく使う項目（表示 ON/OFF・縦軸の目盛り・
  結合）を上に、詳細（Deskew・帯域制限・終端など）は「詳細設定」に折りたたむ。
- **一貫性**：セクション見出し・チップ・ボタンのスタイルを既存 `SectionCard` /
  `StatusChip` / `LabeledValue` に揃える。新規の独自スタイルを増やさない。

## 5. 制約・スタイル

- Kotlin / Jetpack Compose / Material 3。新規依存は追加しない。
- ktlint（`intellij_idea` スタイル、`max_line_length=140`）。作業後に `ktlintFormat` →
  `ktlintCheck` を通す。多行 if/else は必ず `{ }` を付ける（`multiline-if-else`）。
- 文字列はハードコード日本語のまま（今回はリソース化しない）。
- 色は `MaterialTheme.colorScheme` を使い、ダーク/ライト両対応。直書き色は避ける
  （既存で `Color(0xFF..)` を使っている箇所はあるが、新規追加では極力避ける）。
- 横画面（landscape）でも崩れないこと。波形画面は横で拡大する既存挙動を壊さない。
- 既存の `testTag`（UI テストが参照）を安易に消さない。変える場合はテストも直す。

## 6. テスト（必須）

- 変更後、必ず以下を通す（`java` は PATH に無いので JBR を指定）:

```bash
JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew assembleDebug testDebugUnitTest ktlintCheck
```

- **Compose UI テストは日本語ラベル・testTag に依存**している
  （`app/src/androidTest/kotlin/com/pdtoscillo/**`：例 `NavigationTest`,
  `SessionLogTest`, 各画面テスト）。ラベルを変えたら該当アサーションを更新する。
  端末/エミュレータが無ければ instrumented テストは「未実行」と明記する（成功と偽らない）。
- 実機/疑似サーバーでの見た目確認手順（任意だが推奨）:
  1. 疑似サーバー起動: `./gradlew :simulator:run --args="--port 4000 --bind 0.0.0.0 --model DPO4034"`
  2. 端末へ `installDebug`、接続、各画面をスクリーンショットで確認。
  （実機まわりの詳細は `docs/hardware-validation.md` 参照）

## 7. 受け入れ条件（Done の定義）

- [ ] 主要用語に「?」ヘルプが付き、平易な説明が読める（§4.1 の表に沿う）。
- [ ] 概要画面に「自動で見やすくする（オートセット）」があり、確認ダイアログ付きで動く。
- [ ] 「読み取り専用」が「見るだけモード（安全）」等、初心者に伝わる表現になっている
      （既定 ON と拒否の仕組みは維持）。
- [ ] 概要/チャンネル/トリガの情報が整理され、詳細は折りたたみに入っている。
- [ ] 英語ボタン表示が日本語（＋必要に応じ英語併記）になっている。
- [ ] `assembleDebug` / `testDebugUnitTest` / `ktlintCheck` が通る。
- [ ] 変更したラベルに対応する UI テストを更新済み。
- [ ] SCPI コマンド・キュー・ネットワーク・安全確認・読み取り専用の**動作は不変**。

## 8. スコープ外（今回はやらない）

- 画面を丸ごと分ける「かんたんモード」/ フルガイドウィザード。
- 文字列リソース化（i18n）。
- 新機能（新しい測定・トリガ種別の実装など）。
- SCPI/通信/バインド/自動接続のロジック変更。
